Pre-mortem Red Team — TelegramTUI (tg-tui) v1.0.0 Production Deployment & Stability

Deployment of a lightweight (<25MB RAM), 100% keyboard-driven terminal Telegram client in Rust to developers and sysadmins as a daily driver replacement for the official client.

Decision: Ship v1.0.0 publicly on GitHub with prebuilt Windows/Linux binaries, claim production stability, and recommend it as an everyday chat tool.   Horizon: 12 months post-release

Load-bearing assumptions

  • A1: Crossterm and Ratatui will handle all terminal resize events, panics, signal interrupts, and Unicode without corrupting the user's terminal or crashing. load-bearing
  • A2: The client will stay strictly under 25MB RAM in continuous long-running daily usage without memory leaks or unbounded growth. load-bearing
  • A3: The Tokio async event loop and Crossterm input polling will maintain snappy, latency-free (<16ms) typing without keystroke drops under load. load-bearing
  • A4: Message history viewport and scrolling logic will naturally present conversations so incoming updates and navigation are immediately visible. load-bearing
  • A5: The client will gracefully handle network dropouts, sleep/wake cycles, and MTProto reconnection without silent message loss. load-bearing
  • A6: Notification bells and alerts will not cause visual tearing or acoustic spam during high-volume channel activity.
  • A7: The single-line composer widget is sufficient for real-world messages without clipping, text overflow, or editing frustration. load-bearing

Ranked failure modes

#Failure modeBreaksLIPriority
1Terminal State Corruption & Shell Lockout on Panic
A user resized their terminal or encountered unexpected Unicode text; a panic occurred during drawing before raw mode and alternate screen were cleaned up; the user's shell was left broken with invisible cursor and no line echo, forcing them to kill the terminal session.		A14520
2Message History Autoscroll Blindness
Users with active chats (>30 messages) found the history viewport fixed to the top (oldest messages) because no auto-scroll to bottom or dynamic viewport follow was implemented; new incoming messages arrived off-screen, leading users to believe the client stopped working.		A45420
3Long-Running Session Memory Leak from Unbounded Vectors
Power users leaving tg-tui in a background tmux session for multiple weeks found RAM usage ballooning past 800MB due to unbounded push() of all incoming channel messages into memory, completely violating the <25MB RAM pledge.		A24416
4Composer Text Clipping & Overflow on Long Messages
Users typing long messages, URLs, or code snippets found text overflowing the right border without horizontal scrolling or word wrapping; cursor and typed text became invisible, preventing editing or verification before sending.		A75315
5Input Stutter & Dropped Keystrokes Under Network Load
During bulk message sync or channel updates, the main event loop prioritized TDLib channel processing over keyboard polling, causing perceptible lag when typing quickly.		A33412
6Terminal Redraw Tearing from Raw Bell Character
In high-traffic groups, direct raw print!('\x07') to stdout bypassed Ratatui's double-buffering, causing terminal cell tearing, displaced borders, and relentless audio screeching.		A64312
7Silent Message Drop on Network Disconnect
Users pressed Enter on messages while laptop WiFi temporarily dropped; messages remained stuck in pending state without clear offline indicator or retry queue, leaving users unaware their messages were never transmitted.		A53412

Residual risk (accepted knowingly)

External TDLib shared library binary dependency across diverse Linux distributions (glibc vs musl differences on custom kernels) and edge-case terminal emulator escape code differences on legacy Windows conhost.
